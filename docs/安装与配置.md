# 中文安装与配置

适用发布：`v0.1.1-preview.20261019`。本预览版优先使用 macOS ZIP；Windows 停验，Linux 桌面未验收。

![四步接入流程](images/connection-flow.svg)

## 1. 安装

1. 从本仓库对应 Release 下载 `variable-os-dsh-0.1.1-preview.20261019-macos.zip` 和 `SHA256SUMS`。用 `shasum -a 256 文件名` 对照摘要，完整解压并保留 `Variable-Desk` 文件夹。
2. 准备 Node 24；本次复验精确使用 Node 24.19.0。终端执行 `node --version` 确认。包内不含 Node。
3. 打开 `Install.command`，阅读提示并输入 `y`。会联网下载冻结的 pnpm 11.25.0 和官方 DSH 0.2.1-alpha.2，禁用依赖安装脚本，不修改全局 DSH。需要可连接 `registry.npmjs.org`。
4. 安装完成后可按第二次提示输入 `y` 启动；以后用同一文件夹的 `Start.command`。保留启动终端，`Stop.command` 用于停止。

这是未签名、未公证的预览包。遵循 macOS 正常安全确认流程；若系统拦截且无法正常批准，请停止并反馈，不关闭 Gatekeeper、不删除隔离属性。此次终端安装验证不能代替 Finder 下载安全提示验收。

安装位置是 `~/.variable-os-plugin/installation`，工具在 `~/.variable-os-plugin/tools`；已有或失败安装不会被覆盖。不要把这个目录与其他 DSH 安装混用。需要与现有实例并存时，使用独立系统账户或独立 HOME；不要覆盖旧安装、凭证和私卡。

## 2. 打开中文界面

使用启动终端输出的**完整地址**，包括其中的认证参数。只打开 `http://127.0.0.1:端口/` 可能显示 `dsh web authentication required; reopen the URL printed by dsh web.`。遇到此提示，请回到本次启动终端重新打开完整地址；不要将含认证参数的地址发到聊天或公开 Issue。每次启动的端口或认证参数可能改变。

界面保留原中文「变量发现台」。首次空配置没有卡片、没有模型 Key 属于正常状态；安装本身不代表已经连接业主信源。

![首次打开的原中文变量发现台，尚未连接信源](images/03-chinese-desk.png)

## 3. 无需模型 Key 同步业主原卡

1. 打开 [变量服务网站](https://ymj0418.com:18443/)，注册或邮件登录自己的账户。
2. 在账户「服务配置／访问凭证」保存自己的数据访问令牌；确认账户获得 `published` 信源授权。
3. 在「接入说明」下载 API 接入信息或远程 MCP 接入信息 JSON。该文件提供地址和证书指纹，不含个人令牌。
4. 在原插件统一配置页的「信源连接」导入 JSON；填写自己的访问令牌，保存连接，再点「检查连接」。不要填写别人的凭证。
5. 回到变量发现台，等待授权原卡同步，打开「原卡与证据」核对正文、版本及引用。首次全库加载可能较慢，容量边界仍在验收；不要反复重装或并行创建多个同步进程。

![信源设置实际界面，凭证为空](images/02-source-connection.png)

也可手填同站 API 或以 `/mcp` 结尾的地址，但仍需账户页的证书指纹。使用受信 HTTPS 证书时不另填自签 CA；证书变化后重新下载接入信息。不要关闭 TLS 或指纹检查。

读卡和自动更新不调用模型，不消耗本机模型 Key。个人 AI 研究、IMA 订阅和 Tavily 等是另一组可选配置。账户权限、服务额度和服务器状态仍然有效，开源客户端不能绕过它们。

## 4. MCP 与 API

保存并核实同一信源连接后，点插件的「导出 MCP 配置」，将导出的本机 stdio 配置导入支持该配置的 MCP 客户端。配置绑定当前安装和授权，不应共享给其他人；不要把私有路径或令牌提交 Git。

七个只读工具：`research.capabilities`、`search_evidence`、`read_evidence`、`read_card`、`timeline`、`research_context`、`read_wiki`。原卡与引用按信源授权读取，会员研究库检索还需有效深研资格。`research_context` 默认关闭联网搜索；普通 MCP 读卡不是生产或发布入口。

直接远程 MCP 客户端需要 Streamable HTTP 及自定义 Authorization Bearer 支持；仅支持 OAuth 的客户端尚未验收。API 用户从账户页查看接入说明并私下配置 Bearer 令牌。禁止把令牌放入 URL 或公开示例。

## 5. 已有官方 DSH 的 TGZ 路径

此路径要求已安装并核对官方 DSH `0.2.1-alpha.2`、Node 24、pnpm `11.25.0`，且使用独立 HOME／DSH_HOME 和工作目录。它不会应用 ZIP 工具链中的依赖修复，不建议初次用户自行拼装环境。

```sh
node --version
pnpm --version
dsh --version
dsh plugin --profile web add "/absolute/path/to/variable-os-dsh-desk-ui-0.1.1.tgz"
dsh --profile web
```

替换实际绝对路径，从本次启动终端打开完整认证地址。该命令会改变所选 profile，不要在旧生产 profile 中执行。

## 6. 停止、升级和卸载

- 用 `Stop.command` 正常退出。再次 `Start.command` 沿用自己的保存状态，不重复安装。
- 升级前停止实例，再使用**新包**的 `Upgrade.command`，按提示确认；同版拒绝重复升级。跨版本兼容及故障恢复尚有未验收范围，操作前自行保存私有备份。
- 升级事务中断时保留现场，按错误使用 `Recover.command`；不要手动删除锁或覆盖失败目录。
- `Cleanup.command` 和 `Uninstall.command` 会先列明范围，输入 `DELETE` 才永久删除相应私有状态或备份；不熟悉范围时不要确认。
- 退出网站不会自动撤销插件令牌。停止授权访问，应在账户页撤销相应凭证；离线客户端不能保证即时擦除，恢复连接后仍要核实清理结果。

故障反馈只提供版本、系统版本、错误码和脱敏步骤，不上传令牌、带认证参数的地址、私有卡片、数据库或整个配置目录。
